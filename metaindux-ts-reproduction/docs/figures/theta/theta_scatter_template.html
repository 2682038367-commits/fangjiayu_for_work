本页是模板，不是结果。 下面三个面板里的点是我编的示意数据，只用来说明 「拿到真实 θ 之后，散点会长成什么样、各自意味着什么」。真实的 θ 目前还没取出来—— 项目里 7 个种子的 metadata 与 metrics 都没有记录它，需要从 checkpoint 权重里读。

一个必须先定的口径：两个 θ 怎么办

网络里有两个频率模块，各自一个 θ，所以每次实验抽到的是一对数。建议：

  • 主图横轴用两个 θ 的均值，点的标签里写出原始一对（如 0.30/0.05）
  • 若均值看不出结构，再补一张「θ₁ 单独」「θ₂ 单独」的分面图——很可能只有某一个模块在起作用
  • 不要只挑一个模块画：那是挑变量，会让结论失真

怎么取数

在项目 .venv 里跑，几秒钟，不动任何已有文件：

python3 read_theta_from_ckpt.py --scan results/runs --csv theta_values.csv

  • 命中会打印每个 checkpoint 里名字含 threshold 的参数和数值
  • 全部未命中说明 key 名不含这些关键字，加 --all-params 看真实参数名
  • 只读不写，safe

提醒：n 太小，别把相关当因果

FD002 七个点、FD004 五个点。这种样本量下就算算出 |ρ| 很高，置换检验的 p 值也大概率在 0.05 以上。所以这张图的定位是提示性证据——它能把「θ 有关」从猜测抬成 「值得写进报告的观察」，但抬不成「已证实的主因」。报告措辞要留这个余地。
