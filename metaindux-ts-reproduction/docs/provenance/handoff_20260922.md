## 1. 项目在做什么（背景，理解它才能判断合理性）

论文卖点：生成故障数据时，按一个比例 θ **丢掉一部分频率成分**，能让合成数据更逼真，下游剩余寿命（RUL）预测更准。

我们做的事：

- **两臂对照**（FD002）：论文公开代码的路径（θ 随机） vs 我们把 θ 钉死成 0.25。**各跑 7 个 generation seed**，每个再配 5 个 evaluator seed（共 35 次评估）。
- **归因分解**（FD002/FD003/FD004）：我们复现的数字比论文差，把差距劈成两半：
  ```
  总差距 = 协议层 + 生成端
  协议层 = 真实数据对照均值 − 论文值      ← 评估流程差异造成的
  生成端 = 合成数据均值 − 真实数据对照     ← 合成数据质量造成的
  ```

结论（已冻结，见 §5）：**θ 机制的增益没查出来；差距主要来自生成端；协议层的问题只在 FD004 上被证实，原因未明。**

## 3. 任务一：整理目录与代码

请按 `01_conclusions/REPRODUCTION_AUDIT.md` 的 **§1 目录地图** 和 **§2 代码链路** 来做，那两节是最权威的现状描述。要点：

### 3.1 目录整理原则

- **权威产物不得删除或覆盖**（REPRODUCTION_AUDIT.md §1.1 列了清单）。整理 = 移动/归类/加 README，不是清理。
- **禁混用项要物理隔离或打标记**：`results/fd002_evaluation_fixed_split.npz`（sha256 `843652a3…`）是 11 个 FD002 划分文件里唯一的异类，凡由它产出的历史数字**不能与本报告的相减或合并**。建议移到 `results/_deprecated_incompatible_split/` 并在原地留一个 README 说明。
- **中间产物**（§1.2）可重建，允许清理，但清理前先确认不在权威清单里。

### 3.2 代码整理要注意的三个已知陷阱

这三条是我们踩过的坑，整理时**不要把坑埋掉**：

1. **θ 参数陷阱**：公开臂 `hard_random_quantile` 下，`--frequency_threshold_init` **被完全忽略**，只有 `--frequency_threshold` 生效。三种模式的参数不能直接横向比较：
   - `hard_random_quantile`: θ 是分位数参数；
   - `soft`: `0.5 * sigmoid(θ)` 是归一化能量阈值；
   - `STE`: `softplus(θ)` 是归一化能量阈值。
   后两项不是“等效丢弃比例”。跨模式统一使用采样前向实测的 `mask_drop_ratio`：二值 mask 为零元素占比，soft mask 为平均衰减 `mean(1-mask)`。旧图和旧 θ-RMSE 报告未记录前向 mask，不能用于跨模式丢弃率结论。

2. **两臂的 evaluator checkpoint 目录必须分开**。若 resume 复用了对方训好的判别器/预测器，两臂就不是独立评估，配对检验直接失效。整理时别把这两个目录合并。

3. **划分同源是硬保证，别破坏**。真实对照、固定臂合成、公开臂合成三者都用字节级相同的划分文件（sha256 `0b4fd49c…`）。`configs/evaluation_fd002_w48_public_code.yaml` 第 12 行刻意指向 `fd002_fixed_025_seven_seeds_split.npz`，注释也写了原因。改这个指向会让归因恒等式从「严格成立」退化成「近似成立」。

### 3.3 脚本归属

包里 `03_scripts/` 是我们（复现方）写的**分析与核对脚本**，不属于上游源码，建议在项目里单独放一个 `analysis/` 或 `scripts/_repro_audit/` 目录，不要和上游 `scripts/` 混在一起。

## 4. 任务二：核对结果合理性

### 4.1 一键核对（首选，先跑这个）

```bash
cd ~/projects/rul/metaindux-ts-reproduction
cp <本包>/03_scripts/audit_checklist.sh .
bash audit_checklist.sh                 # 默认作用于当前目录
# 或显式指定：bash audit_checklist.sh ~/projects/rul/metaindux-ts-reproduction
```

**只读不写**，输出 `PASS / FAIL / INFO` 计数和需处理清单。43 项分三层：

| 层 | 检查什么 |
|---|---|
| **A 完整性** | 35 行结构、7×5 seeds、manifest 三项、npz 7/7、划分哈希 |
| **B 数值** | 逐 gen RMSE 复算、配对 Δ 与 t 检验、协议层、生成端、交叉验证 |
| **C 统计** | Wilcoxon、35 次 leave-one-cell-out、剔 seed 53、Cochran's Q / I²、FD004−FD002 Welch |

有 FAIL 就把输出贴回给原提问方定位，**不要自行改数据去消掉 FAIL**。

### 4.2 复算冻结数字

```bash
cd ~/projects/rul/metaindux-ts-reproduction
cp <本包>/03_scripts/gen_frozen_numbers.py .
python3 gen_frozen_numbers.py --check     # 只校验，退出码 0 = 全部冻结值复算一致
```

### 4.3 三条最容易踩的核对误区

- **不要用 35 行原始表直接做配对检验**。统计单位是 **generation seed（n=7）**，5 个 evaluator seed 必须先按 gen 取均值；按 35 行算就是伪重复，会把 p 值算小。
- **判别分数（DS）不要求逐位复现**。DS 要重新训练判别器，有浮点非确定性；RMSE 是纯前向推理，应当逐位一致。已知 `(gen=13, eval=3)` 一个格子有 9.268e-03 抖动（相对 11.57%），其余 14 个格子逐位一致，已结案（见 §6）。
- **协议层必须报 CI 和显著性，不能只报点估计**。曾经把 FD003 的 −0.515 写成「协议不构成瓶颈」，但它的 95% CI 是 [−1.853, +0.822] 含 0（p=0.345），正确说法是「无法区分于 0」。

## 7. 红线（违反会毁掉结论的可信度）

1. **禁止挑种子**。7 个种子是预注册的，不许为了显著而增删。seed 53 的 −11.104 **必须如实报告**，不得剔除（已验证剔了结论也不变，留着没有代价，藏着才是问题）。
2. **禁止说「两臂等价」**。只做了差异性检验，没做 TOST 等价性检验。以 ±1.0 RMSE 为等价界时 CI [−6.098, +1.462] 远超边界。正确措辞是「未能检出差异」。
3. **禁止把三个协议层合并成一个数字**。I²=95.6%，它们是三个不同的东西。强行合并会得到 +0.480 这种误导性数字。
4. **禁止把 `results/fd002_evaluation_fixed_split.npz`（`843652a3…`）产出的数字与本报告的相减或合并**。
5. **禁止改动权威产物**（§3.1）。要动就先备份 + 说明。
6. **不显著不等于无效应**。n=7 双尾配对 t 检验的检出下限是 RMSE |Δ|≥5.201、DS |Δ|≥0.242，实测只有 2.318 / 0.121。报告时必须写这句。
